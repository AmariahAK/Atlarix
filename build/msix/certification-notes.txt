Atlarix is a desktop AI coding workstation: it reads and edits the user's own source folders and runs their developer tools.

runFullTrust: packaged Win32 (Electron) app. It starts terminals, git, ripgrep and package managers in the folder the user opens.

unvirtualizedResources (reconsideration, new information):
- Why: our optional browser extension lets the user's AI agent work in the user's own Chrome, Edge, Brave or Vivaldi. On Windows, Chromium finds a native messaging host only through HKCU\Software\<browser>\NativeMessagingHosts\<name>, read from the real registry. From a package hive no browser can see it.
- Alternatives explored: a localhost port (any local process or web page could reach it; native messaging is the browser's own channel, limited to our extension); HKLM (needs admin, machine-wide); enterprise policy (managed PCs only); asking users to run a registry script (error-prone, same keys).
- Least privilege: this package no longer disables registry virtualization. Using Windows 11 flexible virtualization it excludes exactly five keys, one per browser, each named HKCU\Software\<browser>\NativeMessagingHosts\dev.atlarix.bridge (Google\Chrome, Chromium, Microsoft\Edge, BraveSoftware\Brave-Browser, Vivaldi). Every other write stays virtualized. Each key's only value is the path to our host manifest in %USERPROFILE%\.atlarix\chrome.
- Safeguards: the manifest allows only our extension's ID; the host only relays messages to the running Atlarix app for the same user; nothing is elevated; on Windows 10 nothing is unvirtualized.
- Support: support@atlarix.dev, https://www.atlarix.dev
- Assurance: the capability is used only to register this native messaging host, and writes only to the five keys above.

How to test: launch Atlarix, sign in (free, email, Google or GitHub), open any folder, pick "Atlarix Auto" and ask "list the files here and summarize the README".
